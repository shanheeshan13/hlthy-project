1. Feedback & Programme Directory

↗ View Feedback Page ✅ Validation Evidence

HTML Structure

The feedback page (feedback.html) is divided into three distinct sections within <main>:

  • Programme Directory: A <div class="programmes-scroll"> with max-height and overflow-y: auto creates the scrollable region. Four .prog-card elements use a horizontal Flexbox layout — image on the left, text on the right — for an efficient use of space. Cards represent nutrition-focused initiatives including a campus cook-along, community food bank, healthy eating awareness campaign, and a batch cook workshop.
  • Ratings & Reviews: A summary strip and three review cards arranged in a CSS Grid. The numeric rating is displayed using large font sizing within a coloured banner strip for visual impact.
  • Feedback Form: Two <fieldset> elements with <legend> group the form fields semantically. Field types include text, email, tel, textarea, date, datetime-local, select, and datalist — covering all required input types from the brief.

CSS Techniques

  • The scrollable section uses overflow-y: auto; max-height: 520px — a simple and effective approach that keeps the section contained without affecting the rest of the page layout.
  • Custom scrollbar styling with ::-webkit-scrollbar applies the brand colour to the scrollbar thumb for visual consistency with the site palette.
  • Form focus states use border-color + box-shadow on :focus to provide a clear visual indication of the active field, benefiting both sighted and keyboard users.

JavaScript Implementation

  • Live character counter: An input event listener on the #message textarea calculates remaining characters from maxlength - value.length and updates the counter text. The counter turns red below 50 characters remaining.
  • Form validation: The submit event listener uses a reusable validate(inputId, errorId, condition) helper function that adds/removes error classes based on JavaScript conditions — supplementing (not replacing) HTML5 native validation. Custom messages appear near each invalid field.
  • Submission confirmation: On successful validation, the form element is hidden (style.display = 'none') and the confirmation message is revealed, providing clear feedback without a page reload.

2. Team Page

↗ View Team Page ✅ Validation Evidence

HTML Structure

The team page (team.html) uses a four-column CSS Grid (repeat(auto-fit, minmax(220px, 1fr))) for the team member blocks. Each .member-block element uses tabindex="0" and role="button" for keyboard accessibility. The expandable .member-details panel sits below the thumbnail within the same block and is hidden by default using max-height: 0; overflow: hidden; opacity: 0.

CSS Techniques

  • Hover-expand pattern: .member-block:hover .member-details and .member-block:focus .member-details apply max-height: 300px; opacity: 1; padding: 1rem — animating via transition on these properties creates a smooth expand/collapse without JavaScript.
  • Thumbnail hover effects: opacity, transform: scale(), and box-shadow transitions on .member-thumb provide clear visual feedback that the element is interactive.
  • Focus styling: .member-block:focus applies a visible box-shadow outline using the secondary colour, ensuring keyboard users can clearly see which element is active.

3. Content Page — Nutrition & Healthy Eating

↗ View Content Page ✅ Validation Evidence

HTML Structure & Design Choices

The content page covers nutrition and healthy eating in the context of SDG 3. It uses a two-column layout — a sticky internal navigation sidebar on the left and the main article content on the right — consistent with the rest of the website. A .stat-row grid of four colour-coded statistic boxes near the top presents key nutritional health facts visually, improving scannability and breaking up long prose sections.

The page is divided into six clearly labelled sections using semantic heading hierarchy: Introduction, Why Nutrition Matters, The Balanced Plate, Barriers to Healthy Eating, Actions You Can Take, and Further Resources. Each section has a unique id attribute linked to by the sticky side navigation using anchor links (href="#section-id").

Four relevant images are included throughout, each with descriptive alt text. A fixed "Go to Top" button using position: fixed ensures the page remains accessible on longer scrolls.

CSS Techniques

  • Two-column sticky layout: CSS Grid (grid-template-columns: 220px 1fr) positions the sidebar alongside the content. The sidebar uses position: sticky; top: 90px so it remains visible as the user scrolls through long sections.
  • Statistic boxes: The .stat-row uses display: grid; grid-template-columns: repeat(auto-fit, minmax(150px, 1fr)) with each box styled using the brand colour palette and a bold numeric display for visual emphasis.
  • Image styling: All images use border-radius, a subtle border, and max-height: 320px; object-fit: cover to ensure they are responsive and visually consistent across screen sizes.
  • Go to Top button: Implemented using position: fixed; bottom: 2rem; right: 1.5rem with CSS only — no JavaScript required, keeping the implementation simple and robust.

Content Approach

All written content is original and student-focused. Rather than reproducing NHS or UN SDG text, the page addresses practical topics relevant to university students — eating on a budget, understanding the balanced plate, and common barriers like time and cooking confidence — directly connecting everyday choices to SDG 3 outcomes.

4. Challenges & Lessons Learned

Challenge 1 — Form validation UX: The initial form validation showed all error messages at once even if the user had only touched one field, which was confusing. The solution was to validate all fields only on submit, while also adding a blur event listener to each required field so individual errors appear as users leave a field they have not filled correctly.

Challenge 2 — Scrollable section height: Setting max-height on the programme directory required careful calibration — too small felt cramped, too large made the scrolling feel unnecessary. After testing with multiple content lengths I settled on 520px, which shows approximately two cards and hints at the scrollable content below.

Challenge 3 — Writing original nutrition content: Writing genuinely student-focused content without reproducing NHS or UN SDG material took more care than expected. Writing from personal experience as a student helped keep the tone authentic and practical.

Lesson learned: CSS hover-based expand/collapse (used on the team page) is simpler and more accessible than JavaScript show/hide for this type of interaction — but requires careful use of :focus states to also work for keyboard users.

5. Accessibility Considerations

  • Form labels: Every form field has an explicit <label for="..."> pointing to the field's id — not just placeholder text, which disappears on input and is not readable by screen readers.
  • Fieldset and legend: Form fields are grouped into logical sections using <fieldset> and <legend>, which screen readers announce as group context before reading individual fields.
  • Error messages: Validation error messages are positioned immediately after the relevant field so screen readers announce them in context.
  • Team page keyboard access: Each team member block has tabindex="0" and responds to both :hover and :focus CSS states, ensuring hover effects also work for keyboard users without any JavaScript.
  • Alt text: All images across all three pages include descriptive alt text that explains the image content meaningfully rather than using generic labels such as "image".
  • Scrollable region: The programme directory scroll container does not trap keyboard focus — users can tab out of it normally.
  • Semantic HTML: Pages use <header>, <nav>, <main>, <section>, <article>, <aside>, and <footer> to provide a clear document structure for assistive technologies.

6. JANET Compliance

  • All content is original and written by Student 3; no programme descriptions, review text, or nutrition content is copied from external sources.
  • Programme cards reference real types of nutrition initiatives (campus cook-alongs, food bank volunteering, campus awareness campaigns, meal prep workshops) but do not impersonate specific real-world organisations or reproduce their copyrighted materials.
  • The feedback form is a UI demonstration only — no data is submitted to any server, and no personal data is stored or transmitted.
  • Review card content is fictional and created for demonstration purposes within a clearly labelled student coursework project.
  • All external images are royalty-free and referenced in the References section below.
  • External links open in a new tab with rel="noopener" to prevent tab-napping security vulnerabilities.
