1. Shared Template & Global CSS

↗ View Home Page ✅ Validation Evidence

HTML Structure

The shared template establishes the structural foundation for all pages on the HLTHY website. It uses semantic HTML5 elements to ensure accessibility and maintainability:

  • <header> — contains the site identity (logo + site title/tagline) and wraps the <nav> element below it
  • <nav> — an unordered list of links to all main pages; placed below the header with its own background colour for visual separation
  • <main> — the primary content area; unique to each page and never shared
  • <footer> — three-column layout containing site info, page links, and individual student editor/validation links
  • All images include descriptive alt text throughout

CSS Techniques

The global CSS file (style.css) uses CSS custom properties (variables) defined on the :root selector to establish a consistent colour palette and spacing system. This makes it easy for all team members to apply consistent styles without repeating values.

  • Layout: Flexbox is used for the header, navigation bar, footer columns, and card grid. CSS Grid (auto-fit with minmax) is used for the card layout to create a responsive grid that adapts to screen width without media queries.
  • Navigation: The nav ul li a selector applies hover and active state styles. The border-bottom: 3px solid transparent trick ensures hover doesn't cause layout shift.
  • Cards: The .card class uses display: flex; flex-direction: column so that buttons within cards always align to the bottom regardless of content height.
  • Transitions: All interactive elements use transition: 0.25s ease for smooth visual feedback without performance overhead.

Design Rationale

The colour palette is anchored by SDG 3's associated green (#2E7D6E), referencing health, nature, and well-being. A warm orange accent (#F4A261) provides contrast for calls-to-action without conflicting with the primary palette. The neutral off-white background (#F8F9FA) reduces eye strain compared to pure white. Typography uses system fonts (Segoe UI, Arial) for fast loading and broad device compatibility.

2. Home Page

↗ View Home Page ✅ Validation Evidence

HTML Structure

The home page (home.html) uses the shared template and adds bespoke content within <main>. Key structural elements include:

  • A hero <section> with a gradient background, headline, and call-to-action button
  • A mission section containing a <div class="card-grid"> with four <article> elements — using <article> is semantically appropriate as each card is a self-contained piece of content
  • An interactive gallery section using anchor (<a>) elements styled as tiles, each linking to the relevant content page

CSS Techniques

The home page includes embedded CSS (within a <style> block) for page-specific styles that do not belong in the global CSS:

  • The hero section uses a CSS linear-gradient for the background, keeping it lightweight without requiring an image asset
  • The interactive gallery tiles use position: relative on the tile and position: absolute; inset: 0 on the overlay to create a full-cover overlay that responds to hover
  • The "Explore" button within each tile uses opacity: 0; transform: translateY(6px) in the default state and transitions to visible on hover — creating a smooth reveal effect without JavaScript
  • Card list items use a CSS-generated checkmark (content: "✓" with position: absolute) for visual polish

JavaScript

The home page does not use JavaScript — all interactivity is achieved with CSS transitions. This is intentional and appropriate for this page; the gallery JavaScript is reserved for the dedicated gallery.html page.

3. Gallery Page

↗ View Gallery ✅ Validation Evidence

HTML Structure

The gallery page (gallery.html) uses a CSS grid to display thumbnail images, and a hidden <div id="gallery-modal"> element that is populated and revealed by JavaScript when a user clicks a thumbnail. The modal uses role="dialog", aria-modal="true", and aria-labelledby for screen reader accessibility.

JavaScript Implementation

All gallery interactivity is implemented using vanilla JavaScript event listeners — CSS-only tricks such as :target or checkbox hacks are not used, as required by the specification:

  • Hover interaction: mouseenter and mouseleave event listeners on each thumbnail show/hide the caption and apply an outline border, providing clear interactive affordance
  • Click-to-expand: A click event listener calls openModal(index), which uses the galleryData array to populate the modal's src, alt, title, and description fields
  • Close interactions: Three close mechanisms are implemented — clicking the ✕ button, clicking outside the modal box, and pressing the Escape key
  • Keyboard accessibility: Each thumbnail has tabindex="0" and responds to both Enter and Space key events, enabling keyboard-only navigation
  • User customisation: change event listeners on the colour scheme and font selectors call applyTheme() and applyFont() functions that manipulate inline styles on the modal content area

4. Content Page — Mental Health

↗ View Content Page ✅ Validation Evidence

HTML Structure

The content page uses a two-column CSS Grid layout: a sticky side navigation panel on the left and the main article content on the right. This layout is responsive — on screens below 680px, it collapses to a single column using a media query.

  • A single <h1> for the page title, with <h2> for section headings and <h3> for sub-sections — following correct hierarchical order
  • Each section has a unique id attribute that matches the corresponding href="#id" anchor in the side navigation
  • The "Go to Top" button uses position: fixed in CSS to remain visible during scrolling, linking to <span id="top"> at the top of the page — no JavaScript required
  • All four images include detailed, contextually appropriate alt text

Content Approach

All content is original and written by Student 1. It covers the relationship between mental health and SDG 3, the specific impact on university students, and practical actions anyone can take. Factual claims are supported by publicly available statistics from organisations such as the World Health Organization and Student Minds, referenced at the end of this page editor.

5. Challenges & Lessons Learned

Challenge 1 — Gallery modal on mobile: The initial modal design used position: fixed with display: flex, which caused the modal to be partially obscured by the mobile keyboard when the user customisation selects were focused. This was resolved by ensuring overflow-y: auto was set on the modal box, and testing on multiple screen sizes.

Challenge 2 — Sharing the CSS with teammates: When distributing the global CSS, two teammates initially made edits to style.css that affected the nav bar spacing across all pages. We resolved this by adding a prominent comment block at the top of style.css and creating a team agreement about which lines were locked. This taught me the value of clear documentation in collaborative projects.

Challenge 3 — HTML validation errors: The initial version of home.html contained a duplicate id attribute on two card elements and a missing lang attribute on the <html> tag. Running validation early caught these before they propagated to other pages.

Lessons learned: Start with the global CSS and template before writing page content. Validate early and often. Comment your code thoroughly — not just for the marker, but for your teammates.

6. Accessibility Considerations

Accessibility was considered throughout the development of all pages I implemented. Specific techniques used include:

  • Semantic HTML: Using <header>, <nav>, <main>, <footer>, <article>, <section>, and <aside> rather than generic <div> elements. This gives screen readers meaningful context about page structure.
  • Alt text: Every image on every page I implemented includes a descriptive alt attribute that conveys the content and purpose of the image in context, rather than generic descriptions like "image" or file names.
  • Keyboard navigation: Gallery thumbnails have tabindex="0" and respond to keyboard events. The modal can be closed with the Escape key. The side navigation on the content page is fully keyboard accessible.
  • ARIA attributes: The gallery modal uses role="dialog", aria-modal="true", aria-labelledby, and aria-live="polite" on the impact summary. Navigation landmarks use aria-label attributes.
  • Colour contrast: All text-background combinations were checked to ensure sufficient contrast ratio. The primary green (#2E7D6E) on white meets WCAG AA for normal text at 18px and above.
  • Focus styles: The global CSS preserves browser default focus outlines and adds custom focus styles on interactive elements using :focus selectors.

7. JANET Compliance

All pages I implemented comply with JANET (Joint Academic Network) regulations governing the publication of web pages. JANET regulations require that published web content is lawful, accurate, non-offensive, and does not infringe intellectual property rights. My compliance approach includes:

  • Original content: All written content across my pages is original and authored by me. No text has been copied from the UN SDG website or any other source.
  • Image sourcing: All images used are either royalty-free (sourced from iStockPhoto or similar) or placeholder references. All external sources are documented in the References section below, as required.
  • No harmful or offensive material: All content is appropriate for a university educational context. No content promotes discrimination, harassment, or illegal activity.
  • No unauthorised third-party material: No copyrighted music, video, fonts, or code libraries have been used without appropriate licence or attribution.
  • Data privacy: No personal data is collected or stored by my pages. The feedback form (Student 3's page) is designed as a UI demonstration only and does not transmit data to any server.
