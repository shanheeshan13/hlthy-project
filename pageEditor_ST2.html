1. Splash Screen

↗ View Splash Screen ✅ Validation Evidence

HTML Structure

The splash screen (splash.html) is the only page that does not use the shared template, as specified in the brief. It is a full-screen, self-contained page with its own CSS. Key structural elements include:

  • A <div class="bg"> with a CSS ::after pseudo-element overlay, creating a dark tint over the background image to ensure text readability without requiring a separate HTML element
  • A <div class="splash-content"> container using Flexbox to centre all content vertically and horizontally
  • The auto-redirect is implemented using <meta http-equiv="refresh" content="4;url=home.html"> as specified in the brief
  • The group member names are displayed as styled <span> pill elements within a flex container

CSS Techniques

  • Full-screen background: background-size: cover; background-position: center on the .bg element ensures the image always fills the viewport regardless of screen size
  • CSS loader animation: Three .loader-dot elements use a @keyframes bounce animation with staggered animation-delay values (0s, 0.15s, 0.3s) to create a pulsing loading indicator without any images or JavaScript
  • Z-index layering: The background overlay uses z-index: 0 and the content uses z-index: 1 to ensure correct stacking

JavaScript Implementation

  • Countdown timer: A setInterval function decrements a timeLeft variable every 1000ms and updates the visible #countdown-num span via textContent
  • Skip button: The skip button's click handler sets a skipped flag to true, calls clearInterval() to stop the countdown, removes the <meta> refresh tag from the DOM to cancel the auto-redirect, and then manually navigates to home.html

2. Action Impact Simulator (AIS)

↗ View AIS Page ✅ Validation Evidence

HTML Structure

The AIS page (ais.html) presents six action cards within a CSS Grid. Each <article class="action-card"> contains a thumbnail image, heading, description, points badge, and a select/deselect button. A separate <div id="impact-summary"> with aria-live="polite" displays the dynamically updated impact score and feedback message.

CSS Techniques

  • The .action-card.selected class provides visual distinction between selected and unselected cards using a contrasting border colour and background tint
  • The full-page background image is applied to .ais-bg and changed dynamically by JavaScript — a ::before pseudo-element adds a white semi-transparent overlay to keep content readable over any background image
  • Embedded CSS includes at least five clearly commented rules as required by the specification

JavaScript Implementation

The impact tracking logic uses a selectedState boolean array to track which of the six cards are selected. The updateSummary() function iterates over this array, sums the data-points attribute values, and applies threshold logic:

  • Low impact: 0–7 points → orange border, low-impact message, background image A
  • Medium impact: 8–14 points → primary green border, encouragement message, background image B
  • High impact: 15–21 points → dark green border, congratulatory message, background image C

Background changes are controlled entirely by JavaScript via element.style.backgroundImage, as required. Cards respond to both mouse click and keyboard (Enter/Space) events. A reset button clears all selections and restores the default state.

4. Challenges & Lessons Learned

Challenge 1 — Meta refresh cancellation: The specification required both an automatic meta refresh redirect AND a skip button that cancels it. The <meta> refresh cannot be paused or stopped through normal JavaScript once the page has loaded — the solution was to remove the <meta> element from the DOM using document.getElementById('meta-refresh').remove() before the browser processes the redirect. This required research and experimentation.

Challenge 2 — AIS background readability: Setting a full-page background image behind card content created contrast issues. The solution was a ::before pseudo-element on .ais-bg with position: fixed; inset: 0; background: rgba(255,255,255,0.82), which provides a consistent overlay regardless of which background image is shown.

Lesson learned: Always plan the JavaScript data structure before writing the UI. The selectedState array and galleryData object made the logic clean and easy to extend. Starting with the data model first would have saved time.

5. Accessibility Considerations

  • Splash screen background: The background image div uses role="img" and aria-label to describe the decorative background for screen reader users
  • AIS cards: Each card uses aria-pressed (updated by JavaScript on selection) so screen readers announce the selected state to users navigating by keyboard
  • Live region: The impact summary uses aria-live="polite" and aria-atomic="true" so changes are announced without interrupting ongoing screen reader output
  • Reduced motion: The CSS bounce animation on the splash screen should ideally be wrapped in a @media (prefers-reduced-motion: no-preference) query — this is noted as a future improvement
  • Alt text: All images on all my pages include contextual, descriptive alt text
